# ReasonAI proposal recovery

## Scope and root cause

The existing contract is `{ summary, operations }`, not a replacement `{ nodes, edges }` document. Seven operations cover adding, updating and deleting nodes/edges, plus moving nodes. No API contract or document schema was changed.

`provider.ts` receives the model response, parses tool-argument JSON and calls `parseReasonAIProposal` in `contract.ts`. That validator rejects the whole proposal on the first unsupported field/type, missing required value, bad coordinate or invalid reference. `ReasonAIPanel.tsx` repeats validation on receipt. `prepareReasonAIApply` uses the existing factories and simulates changes through `applyCanvasOperation`; the reducer can reject duplicate connections at that stage. No failing production payload was supplied, so a particular failed request cannot be attributed to one field.

The authorized [provider follow-up](reasonai-provider-investigation.md) now runs the same pure sanitizer before provider validation, closing the recoverable pre-browser rejection. Wrong top-level contracts remain intentionally fatal. The original prompt/schema were consistent and remain unchanged.

## Existing contracts

- Node types come from `constants/system-design-palette.ts` (`SYSTEM_DESIGN_NODE_DEFINITIONS`), backed by `types/system-design.types.ts`. They cover clients, networking, compute, data, messaging, external services, modules, boundaries and annotations. Image/freehand additions require asset/drawing data and remain unavailable to AI proposals.
- Edge types come from `SYSTEM_DESIGN_PRIMARY_EDGE_TYPES` and `SYSTEM_DESIGN_LEGACY_EDGE_TYPES` in `constants/system-design-edge-registry.ts`. Primary types: `http_request`, `http_response`, `grpc`, `websocket`, `database_read`, `database_write`, `async_message`, `event_publish`, `event_stream`, `replication`, `batch_transfer`, `failure_fallback`, `custom`. Legacy types remain valid for existing documents.
- Both `read` and `system_boundary` were already supported. A boundary obtains its dimensions and rendering defaults from `createSystemDesignNode`; AI-supplied boundary dimensions are discarded in favor of these defaults.
- The tool schema already derives its supported enum values from those registries. Its server-side prompt remains unchanged.

## Browser behavior

`ReasonAIPanel` now uses parse response → sanitize → strict proposal validation → suggestion cards. Accepting a card still runs strict latest-state validation, trusted object creation, reducer preflight and the existing single-operation commit/undo/live collaboration path. Receiving a proposal never modifies the canvas. There is no batch-accept UI; adding one or auto-applying a whole proposal would change existing behavior.

Repairs are restricted to AI proposals:

- Common relationship aliases become canonical types (`read` → `database_read`, `queue` → `async_message`, etc.); unknown relationships become `custom`.
- Duplicate connections retain the first occurrence, including matches against current context. Deduplication uses endpoints and normalized type and is deliberately stronger than label-based equality: the existing reducer rejects same-type parallel connections on the same ports even when labels differ. The AI context omits port information, so matching existing connections is conservative.
- Unsupported node types are removed with incident AI connections. Supported boundaries retain their type and receive existing factory defaults.
- Missing labels/summary receive defaults; absent optional strings remain valid, and nullable optional strings are normalized where safe. Update operations do not invent absent changes.
- Missing, nonnumeric, nonfinite or out-of-range coordinates receive deterministic fallbacks using palette dimensions and the existing paste spacing. No auto-layout was introduced.
- Missing/invalid temporary references use deterministic collision-checked proposal-local refs; references are remapped safely. Duplicate declarations keep the first. AI-supplied internal add IDs are discarded; real node/edge IDs are still generated by existing factories at acceptance.
- Missing endpoints and self-connections are removed.
- Development warnings include operation indexes, diagnostic codes and relevant IDs/values. Fatal development logs include raw and sanitized proposals and validation reasons. Normal users see “ReasonAI couldn't safely apply this canvas update.”

Fatal cases still include nonobjects, missing/nonarray/oversized operation lists, no usable operations, unknown operations or unsafe fields, oversized/invalid text, stale update/delete targets and remaining strict-schema failures. Locked targets, preview mode and changes to the active canvas are still checked before committing.

## Performance

`ReasonAISuggestions.tsx` now shares a memoized local validation context across cards instead of repeatedly redacting the entire graph for each card on each render. Node/edge lookups use maps. Display-text replacement rules are compiled once per graph/proposal, avoiding repeated ID-regex construction while typing or moving the panel. Memoization follows node/edge/proposal changes. No provider/network latency improvement is claimed.

## Verification and remaining limits

Verification passed:

- `npm run test:system-design-state`: 251 tests, including six new sanitizer scenarios and existing provider, undo/redo, model, serialization and collaboration regressions.
- `npx playwright test e2e/reasonai.spec.ts --workers=1 --reporter=line`: all 17 Chromium tests, including the new repair/accept/undo scenario. The first attempt timed out during development-server startup; a retry against the separately started test-configured server passed.
- `npm run typecheck`.
- Targeted ESLint for all six changed TypeScript/TSX files.
- `git diff --check`.

Next.js reported slow filesystem access and the first root-page compilation took about 108 seconds; a subsequent root request took 72 milliseconds. This is separate from the repeated browser render work addressed here. A production build and the complete unrelated browser suite were not run.

The provider now repairs the same recoverable representation errors as the browser. Fundamentally wrong-contract responses are diagnosed and rejected; the origin of the historical full-canvas response is not proven. Existing per-suggestion undo/redo and collaboration semantics are preserved; a proposal is not converted into a new batch transaction. Placement defaults guarantee safe numbers, not overlap-free design. Architecture quality is deliberately not validated. No backend service, database, API route, manual editing or serialization code was changed. See the follow-up report for its additional files and tests.
